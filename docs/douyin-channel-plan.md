# 抖音渠道双轨方案（2026-06-10 拍板）

## 背景与结论

浏览器自动化（机房 IP + puppeteer）被抖音风控定性为不可信环境：扫码可过但强制二次验证，短信不下发、远程刷脸不可达（PR-S27~S31 已打满补丁，定性为风控硬墙）。**放弃在机房环境继续对抗。**

面向"企业客户授权自己抖音号、我们代发"的 B2B 场景，拍板双轨：

- **A 轨（主线）**：抖音开放平台官方 API，scope `video.create.bind`（"代替用户发布内容到抖音"）。代码已完成（见下），等能力审批通过即插即用。
- **B 轨（保底）**：本地发布客户端（易媒/蚁小二形态）。若 A 轨能力申请被拒，按本文档第 3 节实施。
- **过渡**：现有半自动发布助手继续可用（视频详情页生成绑定文案 → 人工发布 → 勾"已发"落库）。

### 关键合规依据（2026-06-10 官方文档核实）

- 《移动/网站应用能力申请及使用规范》原文："开发者在使用**代替用户发布内容到抖音**的相关能力时，仅可用于**企业内部或者签约的账号**的内容管理。" → B2B 签约客户场景是官方明文允许的用法。
- 之前记录的"注册资本≥50万、仅创作工具类、营销内容不准入"门槛**只针对「发布能力」（SDK/H5 投稿，半自动）**，与 A 轨能力是两回事。A 轨在"能力实验室"申请，门槛未公开，**只有实际提交申请才知道**。
- ⚠️ 持续风险：规范禁止"相似视频发布到多个账号"与营销感内容。矩阵发布必须做足**内容差异化**（不同账号不同模板/文案/封面），否则能力会被回收。每号每日上限 75 条。

## 1. A 轨已落地的代码

| 文件 | 内容 |
|---|---|
| `packages/server/src/services/publisher/douyin-open-api.ts` | OAuth（授权URL/换token/刷新/续期）+ 上传（>50MB 自动分片）+ 创建视频；错误码人话翻译 |
| `packages/server/src/routes/douyin-callback.ts` | `GET /douyin/oauth/callback` 公开回调，state HMAC 签名防伪造，token AES-GCM 加密落库 |
| `packages/server/src/routes/accounts.ts` | `GET /accounts/:id/douyin-oauth-url` 生成授权链接（30 分钟有效） |
| `packages/server/src/services/publisher/adapters/douyin.ts` | 重写：官方调用链 + token 自动续期；未授权/能力未批时返回明确指引 |
| `packages/server/src/config/env.ts` | `DOUYIN_CLIENT_KEY` / `DOUYIN_CLIENT_SECRET` / `DOUYIN_OAUTH_REDIRECT_URL` / `DOUYIN_PRIVATE_STATUS`（默认 1=自见草稿模式） |

### 使用流程（审批通过后）

1. `.env` 配置 `DOUYIN_CLIENT_KEY/SECRET` + `DOUYIN_OAUTH_REDIRECT_URL=https://<域名>/api/v1/douyin/oauth/callback`
2. 账号管理建抖音账号 → 调 `GET /accounts/:id/douyin-oauth-url` → 客户打开链接用抖音 App 确认授权 → 回调自动落 token
3. 正常走批量发布。默认 `private_status=1`（自见）：视频过审后仅作者可见，客户在抖音 App「我>作品」检查后手动改公开。`DOUYIN_PRIVATE_STATUS=0` 可改全自动公开。
4. token：access 15 天 / refresh 30 天，发布时自动续期落库；refresh 临过期自动 renew（官方最多 5 次，之后需重新授权一次）。

### 客户授权体验

客户零部署：发一个授权链接，抖音 App 扫码确认，完成。后续发布全部服务端进行，不需要客户电脑/手机在线。

## 2. 能力申请材料清单（A 轨，下一步行动）

前置（按顺序）：

1. **企业主体开发者账号**（个人主体建不了网站应用）：营业执照 + 对公打款验证，约 3 个工作日。个体工商户对"发布能力"已关闭，对能力实验室能力未明确——企业主体最稳。
2. **ICP 备案域名**（回调域名要求）。新轻量机 119.91.52.13 迁移完成后绑定备案域名。
3. **创建"网站应用"**（不是测试应用——测试应用有调用量清零问题，需上线转正）。
4. 控制台 > 应用详情 > **能力管理 > 能力实验室 > 代替用户发布内容到抖音**，提交申请。

申请理由材料（审核 5 个工作日内反馈，材料越充分越易过）：

- 产品定位：学术期刊知识科普内容管理工具，服务签约企业客户管理**其自有/签约抖音账号**的内容发布（贴官方允许场景原话）
- 产品截图：账号管理页（体现"客户授权自己的账号"）、发布页（体现内容预览、用户主动点发布、可勾选是否同步）
- 使用规范承诺：实时/预设发布均由用户在 BossMate 上自主操作；明确告知同步到哪个抖音号；支持勾选「是否同步」「是否删除」（**前端需补这两个勾选框**——申请前做掉，截图要用）
- 内容样例：选**知识科普向**的成品视频（避免营销感强的期刊推广样例）

被拒处理：看拒因。类目问题 → 调产品定位重新申请；主体门槛问题 → 转 B 轨。

## 3. B 轨：本地发布客户端（保底架构）

原理：把"登录+发布"挪到**客户自己的电脑**（家庭/办公宽带 IP + 真实浏览器指纹），服务器只生成内容、下发任务。这是易媒/蚁小二做桌面软件的根本原因——登录环境可信，抖音几乎不弹新设备验证。

```
┌─────────── 服务器（不变） ───────────┐      ┌──────── 客户电脑 ────────┐
│ 选题/文案/视频合成/审核/排期          │      │ BossMate Agent (托盘程序) │
│ 任务队列: publish_tasks 表           │◄────►│  - 轮询/长连接领任务       │
│ GET /agent/tasks  POST /agent/ack   │ HTTPS│  - 下载视频+文案           │
│ (复用现有 JWT + tenant 隔离)         │      │  - 本地 Chrome(有头,持久   │
└─────────────────────────────────────┘      │    profile)上传发布        │
                                             │  - 回报结果→已发落库        │
                                             └───────────────────────────┘
```

要点：

- **Agent 形态**：Electron 托盘应用（或 Node 单文件 + pkg 打包）。内嵌 Playwright 驱动**有头** Chrome，每账号一个持久 user-data-dir。
- **登录**：首次在客户电脑上扫码（可信环境，秒过）；登录态保存在客户本机，不上传服务器（也规避了凭证托管责任）。
- **复用资产**：现有 puppeteer 发布脚本（browser-session.ts 的上传/发布选择器逻辑）可整体移植——之前卡的只是登录环境，发布脚本本身是通的。
- **任务协议**：服务器加 `publish_tasks` 表（pending/claimed/done/failed）+ 两个路由；Agent 侧 200 行核心逻辑。预估 1-2 周出 MVP。
- **何时启动**：A 轨申请被拒，或有客户明确不接受 OAuth 授权时。

## 4. 决策记录

- 住宅代理/指纹浏览器：**排除**——对抗性手段不可长期维护，撑不起 B2B 产品。
- 服务器迁移（119.91.52.13）不解决本质问题（仍是机房 IP），但备案域名是 A 轨前置，迁移优先级提升。
- 半自动链路保留为永久兜底（演示/过渡均可用）。

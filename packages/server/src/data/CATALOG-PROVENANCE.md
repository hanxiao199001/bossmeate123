# 目录快照来源链

「学科定位」体裁的卖点是**每个数字读者能拿官方目录逐条数出来**。
那么快照自己必须有一条可追溯的来源链，否则卖点没有底座 —— 这份文件就是底座。

**改动任何一份快照，必须同步更新此表。** 没有来源的快照等于没有来源的数字。

### 这次校准改了什么

对校准前的快照做全量 diff，发现 **23 条学科分类与官方不一致（3.5%）**、3 条刊名写法不同：

- 《甘肃行政学院学报》 快照=教育学 → 官方=**政治学**
- 《妇女研究论丛》 快照=教育学 → 官方=**社会学**
- 《改革》 快照=自然资源与环境科学 → 官方=**经济学**
- 《干旱区资源与环境》 快照=综合性社会科学 → 官方=**自然资源与环境科学**
- 《复旦学报(社会科学版)》 快照=经济学 → 官方=**高校学报**
- 快照独有的「综合性高校学报」分类（3 本）官方并不存在，已并回「高校学报」
- …其余 17 条见 `git log` 该次提交

**教育学本数校准前后都是 43，但名单不同** —— 混进了《妇女研究论丛》《甘肃行政学院学报》，
同时漏掉官方归在教育学的《复旦教育论坛》《高校教育管理》，一进一出正好抵平。
**这正是"数字对不代表数据对"的实例**：只核总数永远发现不了，必须逐条 diff。

### 已知边界

官方与旧快照的 3 条刊名写法差异，一律**以官方为准**：

```
外交评论                     （旧快照作「外交评论(外交学院学报)」）
戏剧艺术(上海戏剧学院学报)     （旧快照作「戏剧艺术」）
中共中央党校(国家行政学院)学报  （旧快照作「中共中央党校学报」）
```

后两条意味着：若 `journals` 表里存的是短名（「戏剧艺术」「中共中央党校学报」），
按 `normName` 将**匹配不上**官方条目 → 该刊走 `snapshot_mismatch`、不出稿。
这是**故意选择的方向**：宁可少写一篇，不可对一本刊错误宣称收录。

### 🔴 已测出的缺陷：源数据有「错位一行」，且错在转载站不在解析器

旧 `cssci-2023.json` 正是这条管线的产物。8-11 拿官方表做全量 diff 后，
再回头解析 `raw-cssci-2023.html`，得到决定性结论：

```
可比对 651 行：原位正确 628 ｜ 错配 23
错配中「其分类等于下一行的正确分类」= 18 条
错配中「等于上一行」                = 0 条
```

**错配集中在学科分组的边界上，形态是整段错位一行**（如《敦煌研究》拿到「法学」，
而法学是下一行《法律科学》的）。逐条核对原始 HTML —— **转载站页面里写的就是错的**，
解析器忠实复现。所以 **重新解析救不回来**。

### 对另外两份带学科的快照意味着什么

- `cssci-ext`：**同一个站、同一种三列版式、同一个解析器** → 极可能有同类缺陷，
  量级参考 CSSCI 的 3.5%。它的 27 个分类目前**不应**作为"可查证"对外宣称。
- `pku-core`：版式不同（分类行 + 期刊行，靠"当前分类"向下继承）。
  这种结构一旦漏掉一个分类行，**整块**期刊都会挂到上一个分类下 ——
  错误规模可能远大于 3.5%，也可能为零。**未测，别猜。**
  而它的 148 个细分类正是「学科定位」体裁防同质化的主要依赖。

### 处置

拿到官方来源后按 CSSCI 同样的流程逐份校准（下载 → 解析 → 全量 diff → 重建 → 回填此表）。
在那之前：**只有 CSSCI 的分类数字可以对外宣称"可查证"**。

## 待解：港澳台地区标记与同名碰撞

CSSCI 2023-2024 版将港澳台期刊收进目录本体（不再是单独名录）。官方表**只对真正同名的刊**
加地区括注，全表仅 4 条：

```
#72  地理学报（北京）    #73  地理学报（台湾）
#127 管理学报（湖北）    #128 管理学报（台湾）
```

**风险**：官方未加括注、但现实中存在同名两刊的情形。已知例子是《教育实践与研究》——
台刊与河北的大陆刊同名，而官方表里只有一条、无括注。
若 `journals` 表里的是大陆那本，`lookupByName` 会把它匹配到 CSSCI 条目，
产出「本刊入选 CSSCI」这个**成员资格层面的假阳性 —— 性质等同编造**。

**这份 PDF 解不了**（没有地区列）。需要官方港澳台名单作为地区词表。
在拿到之前，`discipline-cohort` 对已知歧义刊名的处置见该文件 `AMBIGUOUS_NAMES`。

**另注**：`journals.catalogs` 由 `scripts/ingest-domestic-core.ts` 从这批同一份 JSON、
用同一个 `normName` 写入，所以它**不是**独立佐证 —— 同一份证据读了两遍，对同名碰撞零防御力。
（此前 `discipline-cohort.ts` 的注释把它写成"独立佐证"，8-11 已更正。）
